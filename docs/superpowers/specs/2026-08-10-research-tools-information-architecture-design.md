# 研究中心与选号工具信息架构重整设计

日期：2026-08-10

## 背景

当前顶部存在“数据分析、策略实验室、选号工具”三个入口，但页面职责已经互相渗透：

- 数据分析同时包含历史统计、条件生成、回测、策略对比、号码池和福彩3D缩水。
- 策略实验室重复提供条件配置、候选生成和回测。
- 选号工具再次提供号码生成、缩水、整理和本地号码篮。

用户无法仅凭入口名称判断应该去哪里完成任务，同一操作也可能在两个页面形成不同结果、不同存储和不同交互。本次重整不是改菜单文案，而是重新划分“研究”和“执行”的产品边界。

## 设计结论

产品收敛为两个顶级业务入口：

1. `研究中心`：回答“历史发生了什么、某套规则过去表现如何”。
2. `选号工具`：回答“现在怎样生成、筛减、整理、保存和导出号码”。

数据分析和策略实验室合并到研究中心，以二级页签区分“数据观察”和“策略验证”。选号工具保持独立。首页预测入口、隐私入口和 AI 设置保持现状，不纳入本次重整。

统一判断规则：

- 历史事实和统计解释属于数据观察。
- 规则配置、回测和对比属于策略验证。
- 任何最终号码生成、筛减、入篮、复制和导出属于选号工具。

## 目标

- 每项主要功能只有一个权威入口。
- 五个公开彩种共用产品结构，但只显示符合该彩种规则的能力。
- 用户可以完成“看数据 → 验策略 → 去选号”的连续流程。
- 保留旧深链接、旧保存策略和旧号码池数据，不因重整丢失用户内容。
- 复用现有领域算法和 API，不复制第二套统计、回测或选号实现。

## 非目标

- 不新增彩票玩法、预测模型或中奖概率声明。
- 不重写现有统计、策略和选号领域算法。
- 不新增账号、云同步、支付或投注功能。
- 不把首页预测流程并入研究中心。
- 不在本次重整中改变现有黑金视觉品牌。

## 顶级导航

业务导航统一为：

- `预测首页`
- `研究中心`
- `选号工具`

原“数据分析”改名为“研究中心”，原“策略实验室”从顶级导航移除。隐私边界和 AI 设置继续作为辅助入口显示。

研究中心使用以下稳定地址：

```text
/analysis.html?game=ssq&view=data
/analysis.html?game=ssq&view=strategy
```

选号工具继续使用：

```text
/tools.html?game=ssq&tool=quick
/tools.html?game=ssq&tool=conditional
```

`game` 只允许 `ssq`、`dlt`、`3d`、`pl3`、`kl8`。无效值回退到 `ssq` 并显示一次可见提示。`view` 无效时回退到 `data`；`tool` 不受当前彩种支持时回退到该彩种的 `quick`。

## 研究中心

研究中心顶部依次展示：

1. 彩种切换。
2. 二级页签：`数据观察`、`策略验证`。
3. 数据新鲜度、当前样本窗口和娱乐性免责声明。

### 数据观察

数据观察只呈现历史事实，不直接生成候选号码。

保留的通用能力：

- 热号、冷号、遗漏。
- 走势、和值、奇偶、区间、连号、重号等形态统计。
- 最近开奖、开奖日历和数据新鲜度。

保留的数字彩专项能力：

- 百位、十位、个位走势。
- 位置遗漏和出次统计。
- 号码查询与号码属性。
- 和值、跨度、豹子、组三、组六分布。

从数据观察移除：

- 号码筛选器。
- 回测功能和策略对比。
- 我的号码池。
- 福彩3D缩水选号。

数据卡片可以提供“用这些观察条件去研究策略”的次级入口，但不得在本页生成、保存或导出最终号码。

### 策略验证

策略验证吸收原策略实验室和原分析页回测能力，形成唯一策略入口：

- 策略预设与自定义规则。
- 历史回测。
- 多策略对比。
- 保存、载入和删除本地策略。
- 回测指标、随机基准和少量示例号码。

示例号码只用于解释策略结果，不提供复制、下载或加入号码篮操作。页面唯一执行出口为 `使用此策略选号`。

原分析页的通用回测与原策略实验室回测统一调用 `lottery_luck.strategy` 对外提供的策略接口。旧 `lottery_luck.analysis` 回测接口在兼容期内保留，但新界面不再调用，避免同一概念存在两套前端流程。

## 选号工具

选号工具是所有最终号码操作的唯一入口：

- 快速选号。
- 锁号与排除。
- 复式选号。
- 胆拖或数字组选包号。
- 条件选号。
- 预算缩水。
- 号码整理。
- 统一号码篮、复制和 CSV 导出。

`条件选号` 承接原分析页号码筛选器和福彩3D条件缩水，并可接收研究中心传来的策略条件。`预算缩水` 继续负责按金额上限筛减已经生成的候选。原分析号码池迁移到统一号码篮后，分析页不再维护第二套本地号码集合。

选号工具不展示历史走势图、冷热排行榜或回测报告。它可以显示策略来源和必要的成本、覆盖信息，但不复制研究中心的统计页面。

## 五彩种能力矩阵

所有彩种共用页面框架，不共用无差别表单。切换彩种后，不适用的能力直接不渲染，不以禁用控件占位。

| 彩种 | 数据观察重点 | 策略验证重点 | 选号工具重点 |
|---|---|---|---|
| 双色球 | 红球/蓝球分区冷热、遗漏、走势、形态 | 红蓝区规则、窗口回测、策略对比 | 快选、锁排、复式、胆拖、条件选号、预算缩水、整理 |
| 大乐透 | 前区/后区分区统计、和值、奇偶、走势 | 前后区规则、追加成本下的回测与对比 | 快选、锁排、复式、单区/双区胆拖、条件选号、预算缩水、追加与整理 |
| 福彩3D | 百十个位走势、位置遗漏、出次、和值、跨度、形态 | 直选/组三/组六规则与回测 | 直选快选、定位锁排、定位复式、组选包号、条件缩水、预算与整理 |
| 排列3 | 百十个位走势、位置遗漏、出次、和值、跨度、形态 | 直选/组三/组六规则与回测 | 直选快选、定位锁排、定位复式、组选包号、条件缩水、预算与整理 |
| 快乐8 | 1-80冷热遗漏、区间密度、奇偶、重号、连号 | 选一至选十的分玩法规则与回测 | 按玩法快选、锁排、复式、胆拖、条件选号、预算与整理 |

跨彩种切换时，系统必须清除不兼容的临时字段，并显示“已按新彩种规则重置”。保存策略、回测请求和选号请求均带明确 `game_key`，不得跨彩种复用未经验证的条件。

## 研究到选号的数据流

用户在策略验证中点击 `使用此策略选号` 时：

1. 研究中心把已归一化的 `game_key`、策略标识、条件、窗口和显示名称写入一次性 `sessionStorage` 对象。
2. 对象键为 `lottery_research_handoff_v1`，结构带 `version: 1`、创建时间和来源页面；创建后30分钟失效。
3. 页面跳转到 `/tools.html?game=<game>&tool=conditional&source=strategy`。
4. 选号工具读取并再次按当前彩种规则校验条件。
5. 校验成功后预填条件选号表单，并显示“来源：<策略名称>”。
6. 交接对象消费后删除；用户必须主动点击生成，不自动产生号码或加入号码篮。

URL 只保存可分享的页面状态，不承载完整策略条件，避免超长链接和陈旧配置。交接对象不存在、过期或校验失败时，条件选号打开空表单并显示可操作提示。

## 本地数据兼容

### 已保存策略

沿用现有 `lotteryLuck:strategyLab:<game>` 键和数据结构。研究中心从存储键推断旧记录的彩种，再按当前规则校验；包含非法字段的记录保留原始数据但不执行，并标记“需要重新保存”。

### 号码池迁移

首次打开新版选号工具时：

1. 读取原 `lotteryLuck:numberPool:<game>` 分彩种号码池。
2. 按彩种归一化并去重。
3. 合并到 `lottery_tool_basket_v1` 对应彩种。
4. 成功后写入迁移标记，不重复迁移。
5. 本次实现不删除原号码池键，便于回退；后续删除需要单独规格。

数字彩必须保留位序、重复数字和 `play_type`；双色球、大乐透、快乐8按各区无序集合归一化。

## 旧入口兼容

- `/strategy.html?game=<game>` 跳转到 `/analysis.html?game=<game>&view=strategy`。
- 原分析页数据链接保持在 `view=data`。
- 原 `/analysis.html?game=3d&tool=reduction` 跳转到 `/tools.html?game=3d&tool=conditional`。
- 原3D走势、遗漏、出次、冷热、号码查询、号码属性和最近开奖深链接继续映射到研究中心的数据观察面板。
- 兼容跳转保留原 `game` 和合法窗口参数，并使用 `replace`，避免返回键循环。

## 页面状态与并发

- 研究中心的数据观察和策略验证各自维护请求令牌；切换彩种、视图或窗口后，旧响应不得覆盖当前界面。
- 选号工具沿用现有请求令牌和结果归属检查。
- 切换视图不清除已保存策略；切换彩种清除未保存且不兼容的临时表单。
- 浏览器刷新后只恢复 URL 中的彩种、视图和工具，不自动恢复已消费的研究交接对象。

## 错误与空状态

- 历史数据过期：仍允许查看，明确显示最新日期和“不代表未来概率”。
- 历史数据为空：数据观察显示空状态；策略验证禁用回测并解释原因；选号工具的纯组合能力仍可使用。
- 策略回测失败：保留当前规则和上次成功结果，提供重试，不跳转到选号工具。
- 规则交接失败：打开对应彩种的条件选号空表单，显示“策略条件未能带入，请重新选择”。
- 彩种不支持某项工具：回退到快速选号并显示原因。
- 本地迁移失败：保留原号码池和现有号码篮，给出提示，不清空任何一方。

所有页面继续使用“历史统计不代表未来概率”“号码管理不提高中奖概率”等明确措辞。

## 可访问性与响应式

- 彩种切换和二级页签使用明确的 `aria-current` 或 tab 语义。
- 当前彩种、当前视图和策略来源不能只靠颜色表达。
- 桌面研究中心允许数据卡片网格和策略双栏；手机端统一单列，不横向溢出。
- 选号工具继续使用桌面左右工作区和手机底部号码篮，但不得遮挡结果。
- 兼容跳转、规则重置和迁移结果通过可感知状态区域播报。

## 实现边界

前端职责：

- `analysis.html/js` 承载研究中心两种视图和按彩种能力渲染。
- `strategy.html/js` 降为兼容跳转，不再维护独立业务界面。
- `tools.html/js` 增加条件选号、策略交接和旧号码池迁移。
- 顶部导航在首页、研究中心、选号工具及其他公共页面保持一致。

后端职责：

- 复用现有分析、策略、工具领域模块。
- 为前端提供可声明的彩种能力配置，避免在多个 JS 文件硬编码不同矩阵。
- 新界面以策略 API 作为回测和对比的权威入口，以工具 API 作为最终号码生成的权威入口。
- 旧分析筛选/回测接口在兼容期保留，不在本次直接删除。

## 测试与验收

### 能力矩阵

- 五个彩种分别验证数据观察、策略验证和选号工具的可见能力。
- 不适用功能不渲染。
- 彩种切换后无旧字段、旧响应或旧结果残留。

### 职责唯一性

- 研究中心不存在最终号码复制、CSV、号码篮和直接缩水操作。
- 数据观察不存在候选生成与回测表单。
- 策略验证不存在最终号码保存和导出。
- 选号工具不存在历史走势图和策略回测报告。

### 联动与兼容

- 策略条件可从研究中心一次性带入同彩种条件选号。
- 非法或跨彩种交接被拒绝并提示。
- 旧 `strategy.html`、3D缩水和3D统计深链接正确跳转。
- 旧保存策略可读取，旧号码池可幂等迁移且不丢数据。

### 回归与质量

- 分析、策略和选号领域单元测试通过。
- API 路由测试覆盖能力配置和稳定错误语义。
- 真实浏览器覆盖桌面与 390px 手机端、键盘操作、请求竞态和本地存储失败。
- 导航快照验证不再出现第三个“策略实验室”顶级入口。
- 完整测试套件通过后才允许合并。

## 发布顺序

1. 建立统一彩种能力配置与映射测试。
2. 将策略实验室并入研究中心并保留旧路由跳转。
3. 从数据观察移除筛选、回测、号码池和3D缩水。
4. 在选号工具增加条件选号、策略交接和号码池迁移。
5. 统一导航、文案和旧深链接。
6. 完成桌面、手机、存储迁移和全量回归验证。

## 完成标准

用户从任一顶级入口进入后，可以仅凭页面名称判断职责；同一操作只有一个权威入口；五个彩种只显示自身有效能力；研究条件可以无损传递到选号工具；旧链接与本地数据继续可用；没有新增概率或投注承诺。
