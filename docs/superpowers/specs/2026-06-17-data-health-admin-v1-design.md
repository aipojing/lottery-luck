# 数据健康与爬虫中台 V1 设计说明

## 目标

把当前项目从“能分析号码”推进到“能长期运营数据”的状态。用户进入后台后，应能一眼看出每个彩种的数据是否新、历史样本是否够、最近是否抓取成功，以及需要补采哪些数据。

## 范围

V1 覆盖：

- 七个已启用彩种：双色球、福彩3D、七乐彩、快乐8、大乐透、排列3、排列5。
- 数据健康报告：记录数、覆盖日期、最新期、最新开奖日、下一期开奖日、状态、近期缺口。
- 爬虫日志：记录每次抓取的 provider、彩种、页数、写入数、状态、错误信息、耗时。
- 手动补采：后台页面可触发体彩官方自采；福彩爬虫保持 CLI 方式，V1 先显示命令建议。
- 前端独立页面：`admin.html`，从首页、分析页、策略页可进入。

V1 不做：

- 登录权限、远程部署鉴权。
- 第三方开奖源 fallback。
- 后台异步任务队列。手动补采先同步执行，页面显示加载状态。

## 数据模型

新增 `crawl_logs` 表，用于记录爬虫运行结果：

- `id`
- `provider`
- `game_key`
- `source`
- `page_size`
- `pages`
- `wrote_count`
- `status`
- `error`
- `started_at`
- `finished_at`
- `duration_ms`

表由爬虫/仓储初始化函数按需创建，不要求人工迁移。

## 后端接口

新增：

- `GET /api/admin/data-health`
  - 返回每个彩种的数据健康状态和最近抓取日志。
  - 状态分为 `healthy`、`attention`、`empty`。
  - 使用规则表计算下一期开奖日和最近预期开奖日期。
- `POST /api/admin/crawl/sports`
  - 请求字段：`games`、`source`、`page_size`、`pages`。
  - 只调用官方体彩链路：`auto/direct/browser`。
  - 返回写入总数、每个彩种结果和刷新后的健康摘要。

## 前端体验

新增 `admin.html` 和 `admin.js`：

- 顶部 KPI：健康彩种数、需关注彩种数、总样本数、最近抓取时间。
- 数据健康表：每个彩种一行，展示 provider、样本数、覆盖范围、最新期、下一期开奖、缺口数、状态。
- 手动补采面板：可选择体彩彩种、采集源、页数、每页条数，点击后触发补采。
- 最近抓取日志：展示状态、耗时、写入数、错误摘要。
- 质量提示：对样本不足、最新日期落后、近期缺口给出简短建议。

视觉保持已有玄金后台风格，但更偏操作台：密度更高、表格清晰、少装饰。

## 错误处理

- 官方接口 403 时，`auto` 模式切到官方页面浏览器态。
- 浏览器运行时缺失时，返回明确错误，提示安装 Playwright Chromium。
- 单个彩种失败不影响其他彩种；日志中记录失败原因。
- 前端补采失败时保留表格现有数据，并展示错误。

## 测试

- 数据健康纯函数测试：状态、缺口、下一期开奖日。
- 爬虫日志表测试：创建、写入、读取。
- API 测试：健康接口、体彩补采接口。
- 前端资源测试：`admin.html/admin.js` 可被服务，包含核心页面标识。
- 全量测试和 JS 语法检查。
