# 玄学推荐可信度 V3 与生成仪式感设计说明

## 产品定位

V3 继续强化首页核心抓手：用户不是来验证统计预测，而是希望拿到一组“像是为自己算出来”的财运号。产品体验要从“点按钮出号码”升级为“先起局，再成号，再解释为什么适合你”。

本版本仍然坚持娱乐推荐定位，不承诺中奖，不把历史走势包装成可预测未来。号码仍由本地算法生成，AI 只参与个人特征提取和文案增强。

## 目标

- 点击“生成财运号”后增加清晰的起局过程，让用户感到系统正在按步骤推演。
- 生成后补足闭环解释：个人信息、命格、喜用元素、数字尾数、号码组合之间有可读链路。
- 增强短钩子：用“今日财运签”先给用户一个容易相信和记住的判断。
- 加强逐号释义和避开号解释，让每个数字看起来都有来源。
- 将本次生成的关键信息写入本地历史记录，为后续复盘和分享继续使用。

## 用户体验

### 生成前仪式流程

用户点击主按钮后，按钮进入计算状态，首页主结果区展示五步起局过程：

1. 校准本命财格
2. 定今日财位
3. 取财眼尾数
4. 避冲煞号
5. 成财运号

每一步有短文案和完成状态。桌面端显示为内嵌横向步骤条，移动端显示为竖向紧凑步骤。整个过程控制在约 1.5 到 2.5 秒内；如果接口提前返回，也等最短仪式时间结束后再更新号码，避免“闪一下就没了”。

如果接口失败，流程停在失败态，提示“起局失败，请稍后再试”，不清空用户已填信息和上一次结果。

### 今日财运签

生成结果区新增一条“今日财运签”，展示一句短钩子和三枚标签。

示例：

- 短钩子：今日偏财气在东南，宜取 2/7 尾，避 4/9 冲。
- 标签：东南财位、尾 2/7、避 4/9

财运签由本地命格、开奖日、当前城市和 AI 特征共同生成。AI 未启用时使用本地确定性模板。

### 为什么这组号适合你

首页现有解释升级为链路式闭环：

个人信息 -> 本命财格 -> 喜用元素 -> 财眼尾数 -> 号码组合

展示时每个节点只写一句话，避免长篇命理解读压住主结果。用户可以一眼看到“我的输入如何变成号码”。

### 逐号释义

每个推荐号码返回结构化说明：

- 数字
- 元素角色
- 入选理由
- 与财眼或尾数的关系

前端展示为可扫读列表，不做复杂展开控件。双色球和大乐透特别号单独标注“财眼/辅眼”；福彩3D、排列3按位置解释。

### 避开号增强

避开号不仅显示数字，还显示避开原因：

- 与今日冲位相抵
- 与避让元素相冲
- 与本组财眼尾数不合

避开号不与推荐号码重复。快乐8 等号码较多的彩种只展示最多 6 个避开号，避免信息过载。

### 历史留痕

每次生成后，本地历史记录新增以下字段：

- `daily_fortune_sign`
- `ritual_steps`
- `credibility_chain`
- `fortune_eye`
- `avoid_numbers`
- `avoid_reasons`
- `number_reasons`

详情页优先读取这些字段；旧记录缺字段时使用兼容文案，不报错。

## 后端设计

### 预测响应新增字段

`/api/predict` 在保持现有字段兼容的基础上补充：

- `daily_fortune_sign`
  - `headline`
  - `tags`
  - `direction`
  - `lucky_tails`
  - `avoid_tails`
- `ritual_steps`
  - `key`
  - `label`
  - `summary`
- `credibility_chain`
  - `label`
  - `value`
  - `explanation`
- `avoid_numbers`
  - `number`
  - `reason`
- `number_reasons`
  - 继续保留旧列表能力，同时补充结构化字段。

### 算法原则

- 本命财格、喜用元素和避让元素继续由本地个人时空向量推导，DeepSeek 只做偏好校正。
- 今日财位按开奖日干支、用户当前城市散列和日期稳定生成，同一输入同一日期保持稳定。
- 财眼尾数来自喜用元素和 AI 数字偏好；AI 未启用时走本地元素尾数映射。
- 号码选择仍使用现有评分体系，V3 只增强解释层和少量权重映射，不引入随机大幅波动。
- 所有文案必须保持“娱乐推荐”口径，避免“必中、稳赚、预测准确”等表达。

## 前端设计

### 首页新增区域

- 主结果区下方新增 `dailyFortuneSign` 容器。
- 表单提交后展示内嵌 `ritualSteps` 步骤条，不使用遮罩层，避免挡住号码区和表单。
- 现有 `credibilityChain` 改为使用后端结构化链路。
- `fortuneHook` 区域承接短钩子和三枚标签。
- `avoidNumbers` 区域展示原因而不只是数字。

### 状态处理

- `idle`：展示上一次结果或默认占位。
- `casting`：显示起局步骤，禁用主按钮。
- `ready`：更新号码、财运签、闭环解释和历史记录。
- `error`：保留旧结果，给出失败提示。

### 移动端

移动端保持单列，不增加新的横向滚动。步骤条采用竖向列表，财运签限制两行内，号码释义使用紧凑卡片。

## AI 使用

DeepSeek Flash 仍然只做两件事：

- 提取用户个人特征：五行偏好、数字偏好、主题气口。
- 生成短钩子和长解读的候选文案。

后端必须对 AI 输出做本地约束：不得接收 AI 直接给出的号码，不得展示中奖承诺，不得让 AI 覆盖本地规则范围。

## 非目标

- 不新增独立页面。
- 不做登录和云端用户系统。
- 不做支付、会员或真实投注引导。
- 不改分析中心、策略实验室和后台的信息架构。
- 不删除七乐彩、排列5 的底层规则，只继续在首页可见彩种范围内聚焦。

## 测试与验证

- 预测引擎测试覆盖新增字段、稳定性、避开号不重复、AI 未启用 fallback。
- API 测试覆盖 `/api/predict` 返回结构和首页 shell 新容器。
- API shell 静态断言覆盖起局步骤容器、财运签容器、历史记录字段名称。
- JS 语法检查覆盖 `app.js`、`result.js`。
- 浏览器截图检查桌面和移动端首页，确保起局步骤、财运签和号码球不互相遮挡。

## 交付顺序

1. 后端补充 V3 字段和本地确定性生成逻辑。
2. 首页接入起局步骤和财运签展示。
3. 历史记录和详情页兼容新字段。
4. 完成测试、截图验证、提交推送。
