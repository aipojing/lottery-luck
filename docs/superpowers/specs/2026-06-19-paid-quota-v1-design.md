# 付费额度系统 V1 设计

日期：2026-06-19

## 背景

当前产品已经具备玄学起盘、基础分析、历史留痕和开奖复盘。下一步商业化不能只做“未体验先付费”，否则用户不知道自己为什么付钱。V1 要把免费体验、预测额度、云端档案分清楚：用户先能使用分析工具和少量预测，再为持续预测、完整解读和长期记录付费。

## 目标

- 预测生成支持额度控制，次数由后台配置。
- 分析工具保持免费可用，用来建立信任和日常使用频率。
- 免费用户的生成记录继续保存在浏览器本地。
- 付费用户的生成记录、号码池和复盘结果进入云端档案。
- 首页明确展示今日剩余额度，让用户知道为什么可以生成或需要解锁。
- 后台可调整免费次数、会员次数、次数包和不同模式的扣减规则。

## 非目标

- V1 不接真实微信、支付宝或银行卡支付，只预留购买和会员接口结构。
- V1 不做完整账号体系，先使用本地模拟用户与会员态，后续再替换成真实登录。
- 不把付费描述为提高中奖率，不承诺命中结果。
- 不限制基础分析页、策略页和历史数据工具的访问。

## 产品分层

### 免费用户

- 可使用全部基础分析工具。
- 每日获得后台配置的免费预测次数，例如 1 次。
- 新用户可获得后台配置的首次赠送次数，例如 3 次。
- 生成记录只保存在当前浏览器本地。
- 页面提示“已保存到本机，开通后可同步云端档案”。

### 付费用户

- 可使用会员每日预测次数或已购买次数包。
- 生成记录自动同步到云端档案。
- 云端保存历史财运号、号码池、开奖复盘和长期统计。
- 可跨设备查看记录。
- 可解锁更完整的大师解读、逐号释义、未来择日和会员模式。

### 分析工具

热冷号、遗漏、走势、和值、奇偶、号码筛选、策略回测、开奖日历保持免费。它们是获客和信任基础，不作为 V1 的主要付费墙。

## 额度规则

额度来源按优先级扣减：

1. 新用户赠送次数。
2. 当日免费次数。
3. 会员每日次数。
4. 已购买次数包。

后台配置字段：

```json
{
  "prediction_quota": {
    "free_daily": 1,
    "new_user_bonus": 3,
    "member_daily": 20,
    "package_units": [6, 18, 66],
    "mode_costs": {
      "steady": 1,
      "partial": 1,
      "guard": 1
    },
    "enabled_games": ["ssq", "dlt", "3d", "pl3", "kl8"],
    "allow_demo_after_exhausted": true
  }
}
```

如果额度不足，`/api/predict` 不直接返回正式起盘结果，而是返回额度不足状态和解锁建议。前端将按钮文案切换为“解锁今日财运号”。

## 后端结构

新增额度与档案模块，保持与预测算法解耦：

- `quota.py`：计算可用额度、扣减额度、返回额度摘要。
- `cloud_records.py`：保存云端生成记录、号码池和复盘结果。
- `api.py`：
  - `GET /api/quota/status` 返回当前用户额度、会员态和后台配置摘要。
  - `POST /api/quota/mock-unlock` V1 模拟解锁次数包或会员态。
  - `POST /api/predict` 在生成前检查额度，成功后扣减。
  - `POST /api/cloud/fortune-records` 保存云端记录。
  - `GET /api/cloud/fortune-records` 读取云端记录。

V1 的用户标识先使用请求头或前端生成的本地 `client_id`。真实登录上线后，`client_id` 迁移为用户 ID。

## 前端体验

首页表单区域增加额度状态：

- “今日剩余 1 次”
- “会员剩余 20 次”
- “次数已用完”

生成成功后：

- 免费用户：显示“已保存到本机”。
- 付费用户：显示“已同步云端档案”。

额度不足时：

- 保留当前结果不清空。
- 打开解锁面板，展示“继续起盘”“云端保存”“开奖后复盘”“多设备同步”。
- V1 提供“模拟开通会员”和“模拟购买次数包”按钮，便于产品链路验证。

历史记录区增加存储标识：

- 本机记录
- 云端记录
- 待同步

## 云端记录数据

云端记录保存字段与本地记录兼容：

```json
{
  "id": "record-id",
  "client_id": "local-client-id",
  "game_key": "ssq",
  "mode_key": "steady",
  "numbers": {"main": [1, 2, 3, 4, 5, 6], "special": [7]},
  "input_summary": "1990/01/01 · 北京市",
  "master_ritual": {},
  "fortune_report": {},
  "review": {"status": "pending"},
  "created_at": "2026-06-19T12:00:00+08:00"
}
```

不得保存完整姓名、完整出生地详细地址等敏感原文。V1 只保存前端现有的输入摘要和生成结果。

## 后台配置

后台新增“商业化配置”卡片：

- 免费每日次数。
- 新用户赠送次数。
- 会员每日次数。
- 各模式扣减次数。
- 次数包规格。
- 额度不足后是否允许演示盘。

V1 先展示当前配置和本地编辑状态。保存配置可写入现有 settings 文件或内存配置，后续再接正式管理权限。

## 风控与合规

- 页面不出现“必中”“保证中奖”“提高中奖率”等承诺。
- 付费权益描述为娱乐起盘、记录保存、云端同步、复盘服务。
- 支付弹窗保留理性提示：本结果仅供娱乐与数据分析参考。
- 额度不足时不制造焦虑，不使用倒计时压迫。

## 测试

- 后端测试覆盖额度状态、额度扣减、额度不足、会员额度、次数包额度。
- API 测试覆盖 `/api/predict` 有额度成功、无额度返回解锁状态。
- 前端行为测试覆盖剩余额度展示、额度不足解锁面板、本地记录和云端记录标识。
- 回归测试覆盖分析页和策略页不受额度限制。
- 静态文案测试确保不出现中奖承诺。

## 成功标准

- 用户可以免费使用分析工具和有限次数预测。
- 后台能控制免费次数、会员次数和模式扣减。
- 次数用完时，首页出现清晰的付费解锁路径。
- 付费态下生成记录进入云端档案，本地记录仍兼容。
- 预测算法、玄学解释和分析工具不因为商业化改造出现回归。
