# 福彩数运合参预测网页设计

日期：2026-06-15

## 背景

当前目录已有中国福利彩票历史开奖数据，来源记录在 `cwl_history/metadata.json`：

- 数据源页面：https://www.cwl.gov.cn/ygkj/wqkjgg/
- 数据生成时间：2026-06-15T05:53:58+00:00
- 历史覆盖：
  - 双色球：2013-01-01 至 2026-06-14，共 2025 期
  - 福彩3D：2013-01-02 至 2026-06-14，共 4660 期
  - 七乐彩：2013-01-02 至 2026-06-12，共 2025 期
  - 快乐8：2020-10-28 至 2026-06-14，共 1976 期

用户希望基于这些历史数据，再结合用户填写的生辰八字相关信息、出生地、当前城市等空间信息，计算未来一段时间内哪天运气最好，并用历史趋势与最佳幸运日一起生成新的预测号码。

## 产品目标

做一个“后端计算 + 前端展示”的预测网页，面向任何用户填写个人信息后生成娱乐性质的四种彩票预测结果。

页面必须做到：

- 展示四个彩种的历史数据摘要与最近开奖。
- 支持切换双色球、福彩3D、七乐彩、快乐8。
- 用户可填写姓名、出生日期、出生时辰、出生地、当前城市。
- 在未来 30 天内按各彩种开奖节奏寻找最佳幸运开奖日。
- 用“历史趋势 50% + 个人时空 50%”生成预测号码。
- 同样输入得到同样输出，避免每次刷新都变化。
- 明确提示结果仅供娱乐，不构成投注建议。

## 非目标

- 不承诺或暗示提高中奖概率。
- 不接入真实支付、投注、账户、登录或用户数据存储。
- 不让 AI 直接决定号码或最佳日期。
- 不长期保存用户姓名、出生信息和城市信息。
- 不实现严肃命理排盘软件；八字相关信息用于生成可解释的娱乐化权重。

## 信息架构

页面采用“数据 + 运势融合”的视觉方向。

首屏包含：

- 彩种切换：双色球、福彩3D、七乐彩、快乐8。
- 数据状态：最近数据日期、数据期数、数据来源。
- 个人信息表单：姓名、出生日期、出生时辰、出生地、当前城市。
- 预测结果：最佳幸运开奖日、幸运分、预测号码、生成说明。

下方包含：

- 最近开奖记录列表。
- 热号、冷号、遗漏号。
- 近期走势和号码区间分布。
- 销售额、奖池或可用奖金信息摘要。
- 当前预测的历史依据与个人时空依据。

## 彩种规则

每个彩种使用独立号码规则：

- 双色球：红球 6 个，范围 1-33，不重复；蓝球 1 个，范围 1-16。
- 福彩3D：三位数字，范围 0-9，可重复，保留顺序。
- 七乐彩：基本号 7 个，范围 1-30，不重复；特别号 1 个，范围 1-30，并与基本号不重复。
- 快乐8：预测 10 个候选号，范围 1-80，不重复。历史展示保留每期 20 个开奖号。

## 系统架构

采用后端负责计算、前端负责展示的架构：

- 后端服务：读取 SQLite/JSONL 历史数据，运行爬虫更新、历史统计、个人时空评分、DeepSeek flash 特征提取、预测合成。
- 前端页面：实现“玄金私享盘”黑金视觉，提交用户输入，展示最佳幸运日、预测号码、依据摘要和历史数据。
- 数据库：以 `cwl_history/cwl_history.sqlite` 为基础，存储开奖、奖级、爬取元数据、可选 AI 特征缓存。
- 定时任务：每天自动抓取官方最新开奖数据，幂等写入数据库。

后端优先提供两个核心接口：

- `GET /api/games`：返回彩种列表、数据覆盖时间、最新期号、最新开奖日期。
- `POST /api/predict`：输入彩种和用户信息，返回最佳幸运日、幸运分、预测号码、历史依据、个人时空依据、最近开奖摘要。

## 数据方案

历史数据来自：

- `cwl_history/ssq.jsonl`
- `cwl_history/3d.jsonl`
- `cwl_history/qlc.jsonl`
- `cwl_history/kl8.jsonl`
- `cwl_history/metadata.json`
- `cwl_history/cwl_history.sqlite`

官方抓取入口沿用本地元数据记录：

- 页面：https://www.cwl.gov.cn/ygkj/wqkjgg/
- API：https://www.cwl.gov.cn/cwl_admin/front/cwlkj/search/kjxx/findDrawNotice

数据库至少包含：

- `draws`：开奖主表，主键为 `game_key + issue`。
- `prizegrades`：奖级明细，主键为 `game_key + issue + grade_index`。
- `crawl_runs`：每次抓取的开始时间、结束时间、结果、写入数量、错误信息。
- `ai_feature_cache`：可选 DeepSeek flash 特征缓存，主键为输入归一化后的 hash，不保存明文姓名和完整出生信息。

### 每日爬虫

每日爬虫作为后端命令和定时任务存在：

```text
python -m lottery_luck.crawler --games ssq,3d,qlc,kl8 --since-latest
```

爬虫规则：

- 每天按固定时间运行一次，默认北京时间 22:30 后执行。
- 每个彩种从数据库最新期号开始增量抓取。
- 抓取结果幂等 upsert，重复期号不重复写入。
- 请求失败时记录 `crawl_runs`，不删除旧数据。
- 官方接口不可用时，预测仍使用已有数据库数据，并在接口返回中标记数据日期。
- 爬虫保持低频请求，不做高并发抓取。

后端运行时按需生成预测摘要：

- 每个彩种的元信息、数据覆盖时间、最新期号。
- 最近 30-100 期记录。
- 全量频率统计。
- 最近加权频率统计。
- 遗漏期数统计。
- 区间分布、奇偶分布、和值范围。
- 销售额和奖池摘要。

## 预测模型

模型分为两个分数：历史趋势分与个人时空分，各占 50%。

### 历史趋势分

对每个候选号码计算：

- 全量出现频率。
- 最近 N 期加权出现频率，越近权重越高。
- 遗漏期数，避免只追热号。
- 区间均衡，防止全部集中在一个数字段。
- 彩种特有约束，例如双色球红蓝分开计算，福彩3D按位置计算。

历史趋势分输出为 0-100。

### 个人时空分

个人时空分把姓名、出生时间、出生地、当前城市、候选开奖日转换为稳定的数字特征。AI 可以参与特征解释，但不能直接输出号码或日期。

总公式：

```text
个人时空分 =
  出生时间结构分 * 0.30
+ 姓名数理分 * 0.15
+ 出生地/当前城市空间分 * 0.20
+ 开奖日共振分 * 0.20
+ AI 特征分 * 0.15
```

若 AI 不可用或返回不合格，`AI 特征分` 用确定性算法兜底，不影响预测可用性。

#### 输入归一化

后端先把用户输入归一化：

- 姓名：去除首尾空格，保留中文、英文、数字，连续空白合并。
- 出生日期：转换为 `YYYY-MM-DD`。
- 出生时辰：转换为 12 个传统时辰之一；未填写时使用 `unknown`。
- 出生地：标准化城市字符串。
- 当前城市：标准化城市字符串。
- 彩种：转换为 `ssq`、`3d`、`qlc`、`kl8`。
- 候选开奖日：转换为 `YYYY-MM-DD`。

归一化后生成稳定 seed：

```text
personal_seed = sha256(
  game_key + "|" +
  normalized_name + "|" +
  birth_date + "|" +
  birth_hour + "|" +
  birth_place + "|" +
  current_city
)
```

这个 seed 只用于计算，不需要长期保存明文输入。

#### 出生时间结构分

出生时间转为简化五行向量：

```text
birth_vector = normalize(
  year_element * 0.25 +
  month_element * 0.30 +
  day_element * 0.30 +
  hour_element * 0.15
)
```

第一版不做完整专业排盘，而使用可复现的简化映射：

- 年：按年份对 10 天干、12 地支取模。
- 月：按月份映射季节五行。
- 日：按公历日期序号取 60 甲子循环。
- 时：按传统时辰映射地支。

号码也映射为五行：

```text
1, 2 -> 木
3, 4 -> 火
5, 6 -> 土
7, 8 -> 金
9, 0 -> 水
```

号码的出生时间结构分为：

```text
birth_time_score(number) = birth_vector[number_element] * 100
```

#### 姓名数理分

姓名不交给 AI 直接解释号码，而先转成稳定数理特征：

- `name_hash`：姓名字符串的 sha256。
- `name_length`：姓名字符数。
- `char_sum`：所有字符 Unicode code point 求和。
- `stroke_like`：第一版使用 `char_sum % 81 + name_length` 作为可复现的娱乐化数理值；后续可替换为真实笔画库。

姓名对号码的偏好：

```text
name_score(number) =
  0.45 * normalized_mod_match(name_hash, number)
+ 0.35 * normalized_mod_match(stroke_like, number)
+ 0.20 * normalized_mod_match(char_sum, number)
```

这里的 `normalized_mod_match` 输出 0-100，用固定取模距离计算，保证同样姓名稳定。

#### 出生地/当前城市空间分

空间分优先使用城市坐标；没有坐标时使用城市文本 hash 兜底。

空间特征：

- 出生地经纬度。
- 当前城市经纬度。
- 两地距离。
- 从出生地到当前城市的方位角。
- 两个城市名 hash。

空间分：

```text
space_score(number) =
  distance_band_match * 0.30
+ bearing_element_match * 0.35
+ city_hash_match * 0.35
```

方位角映射：

- 东、东南偏木。
- 南偏火。
- 中央和近距离偏土。
- 西、西北偏金。
- 北偏水。

#### 开奖日共振分

对未来 30 天每个候选开奖日生成日期向量：

- 年月日的 60 甲子简化索引。
- 星期。
- 日期数字和。
- 与用户出生日期的天数差。

开奖日对用户的共振：

```text
date_resonance =
  cosine_similarity(birth_vector, date_vector) * 0.55
+ seeded_cycle_match(personal_seed, draw_date) * 0.45
```

号码级开奖日共振分：

```text
date_score(number, draw_date) =
  date_resonance * 70
+ normalized_mod_match(draw_date_hash, number) * 30
```

#### AI 特征分

AI 只做结构化特征提取和解释，不做最终决策。第一版指定使用 DeepSeek flash；后端通过 `DEEPSEEK_API_KEY` 启用，未配置时自动使用确定性兜底。

DeepSeek flash 输入：

- 姓名。
- 出生日期。
- 出生时辰。
- 出生地。
- 当前城市。
- 彩种。
- 后端已算出的确定性五行向量和空间摘要。

DeepSeek flash 必须输出 JSON：

```json
{
  "element_bias": {
    "wood": 0.20,
    "fire": 0.25,
    "earth": 0.20,
    "metal": 0.20,
    "water": 0.15
  },
  "digit_bias": {
    "0": 0.08,
    "1": 0.10,
    "2": 0.12,
    "3": 0.10,
    "4": 0.09,
    "5": 0.11,
    "6": 0.10,
    "7": 0.10,
    "8": 0.11,
    "9": 0.09
  },
  "lucky_themes": ["金", "火", "东南"],
  "explanation": "输入呈现金火偏旺，适合选择稳中带升的数字结构。",
  "confidence": 0.72
}
```

DeepSeek flash 限制：

- 不允许返回具体预测号码。
- 不允许返回“必中”“保证”等措辞。
- `element_bias` 和 `digit_bias` 必须归一化。
- `confidence` 超过 0.85 时后端仍按 0.85 处理，避免 AI 过度自信。
- 解析失败、字段缺失、归一化失败、请求超时或 API key 缺失时丢弃 AI 结果。

AI 特征分：

```text
ai_score(number) =
  ai_element_bias[number_element] * 60
+ ai_digit_bias[number_last_digit] * 40
```

AI 分只占个人时空分的 15%，也就是最终号码分的 7.5%。因此 AI 能增加“灵性”和解释感，但不能接管预测。

#### 个人时空分汇总

每个号码的个人时空分：

```text
personal_score(number, draw_date) =
  birth_time_score(number) * 0.30
+ name_score(number) * 0.15
+ space_score(number) * 0.20
+ date_score(number, draw_date) * 0.20
+ ai_score(number) * 0.15
```

输出范围归一化到 0-100。

### 最佳幸运日

对未来 30 天内的候选开奖日计算每日幸运分。

候选开奖日根据彩种规则从历史开奖星期推导：

- 福彩3D、快乐8：按历史节奏近似每日候选。
- 双色球：按历史开奖星期推导为周二、周四、周日。
- 七乐彩：按历史开奖星期推导为周一、周三、周五。

选择幸运分最高的一天作为最佳幸运开奖日。

幸运日分公式：

```text
daily_luck_score(draw_date) =
  cosine_similarity(birth_vector, date_vector) * 0.40
+ seeded_cycle_match(personal_seed, draw_date) * 0.25
+ space_day_match(space_vector, date_vector) * 0.20
+ historical_weekday_strength(game_key, weekday) * 0.15
```

其中 `historical_weekday_strength` 来自该彩种历史开奖日的销售额、奖池或一等奖数量等可用指标的归一化摘要；如果该指标缺失，则使用中性值 50。

### 号码生成

对候选号码计算综合分：

`综合分 = 历史趋势分 * 0.5 + 个人时空分 * 0.5`

然后按彩种规则选出号码：

- 不重复型彩种：按综合分排序后选择，并做区间均衡修正。
- 福彩3D：按百位、十位、个位分别评分，可重复。
- 双色球和七乐彩：主号与特别号/蓝球分开评分。
- 快乐8：输出 10 个候选号，同时展示它是候选组合，不是官方投注格式限制说明。

## 交互设计

后端返回：

- `best_draw_date`：最佳幸运开奖日。
- `luck_score`：幸运分。
- `numbers`：预测号码。
- `history_basis`：历史趋势依据。
- `personal_basis`：个人时空依据。
- `ai_basis`：AI 特征摘要；AI 不可用时返回兜底说明。
- `recent_draws`：最近开奖。
- `disclaimer`：娱乐提示。

默认状态：

- 默认彩种为双色球。
- 表单可为空，空值时使用页面默认示例输入生成演示结果，并提示填写个人信息可获得个人化结果。
- 数据状态显示最新开奖日期和期号。

用户操作：

- 切换彩种时立即刷新历史摘要和预测规则。
- 修改姓名、出生信息或城市后点击“生成预测”。
- “换一组解释”不改变号码，只切换解释文案；同样输入的号码必须稳定。
- 可查看“计算依据”，展开后显示历史趋势与个人时空各自贡献。

错误处理：

- 出生日期缺失：允许生成演示预测，但提示需要填写日期才能个性化。
- 时辰缺失：默认使用“未知时辰”，降低个人时空解释置信度。
- 城市缺失：使用空字符串参与哈希，并提示可补充空间信息。
- AI 不可用：使用确定性算法兜底，页面不报错，只在依据中标记“AI 特征未启用”。
- 数据缺失：隐藏对应统计模块，保留可计算模块。

## 视觉设计

采用已锁定的“玄金私享盘”方向：

- 整体是黑金私享工具，不做营销落地页，也不做普通 SaaS 仪表盘。
- 色彩以黑玉、香槟金、朱砂红为主，蓝球只用深宝石蓝。
- 首屏视觉焦点必须是“今日财运号”、最佳幸运日和预测号码。
- 输入区收敛为低干扰控制条，不抢主视觉。
- 历史依据只在首屏底部轻量展示，可展开查看详情。
- 不堆叠卡片，不做层层嵌套。
- 号码球视觉清晰，红蓝或彩种差异必须一眼可辨。
- 历史数据图表保持简洁，优先使用条形、分布格、趋势线等易读形式。
- 页面必须在移动端与桌面端都能正常阅读和操作。

## 隐私与责任提示

后端接收个人输入用于即时计算。默认不长期保存用户姓名、出生日期、出生时辰、出生地、当前城市明文。

可保存的只有：

- 预测请求的匿名 hash。
- AI 特征缓存的匿名 hash。
- 不含明文个人信息的统计日志。

如果后续需要保存用户历史预测，必须单独增加明确授权和删除能力。

页面必须展示清晰提示：

> 本页面仅做历史数据与娱乐化个人时空特征的可视化预测，不构成投注建议，也不保证任何开奖结果。

提示位置：

- 首屏预测结果附近。
- 页脚。

## 验证计划

实现后需要验证：

- 数据库初始化可读取现有 jsonl/sqlite 文件，并保持 `draws`、`prizegrades` 数据一致。
- 每日爬虫能从官方 API 增量抓取并幂等写入数据库。
- 官方 API 不可用时，服务能使用已有数据继续预测并返回数据日期。
- 四个彩种都能通过后端接口展示最近开奖记录。
- 四个彩种都能通过后端接口生成符合号码规则的预测结果。
- 同样输入重复生成结果一致，包括 AI 不可用时的一致性。
- 修改姓名、生日、时辰、出生地或当前城市会影响预测结果。
- 未来 30 天最佳幸运日落在该彩种候选开奖日内。
- AI 返回具体号码时后端会忽略该字段或判定无效。
- AI 返回非法 JSON、缺字段或过度自信时使用确定性兜底。
- 页面在桌面和移动宽度下没有明显文本溢出或布局重叠。
- 责任提示在首屏或结果区域可见。
