# 玄学推荐引擎 V2 设计说明

## 产品定位

本项目不以“提高中奖概率”作为核心承诺。首页体验改为“玄学财运推荐”：用户填写姓名、历法、出生日期、时辰、出生地和当前城市后，系统基于个人时空、AI 命理解读、开奖日运势和少量历史数据托底，生成一组有仪式感和解释感的财运推荐号。

## V2 范围

- 首页文案从“预测”调整为“推荐/财运号/合参推荐”，降低预测承诺感。
- 后端预测返回 `recommendation_basis`，明确玄学主导权重：
  - `personal_space`: 40
  - `ai_fortune`: 25
  - `draw_day_luck`: 20
  - `history_guardrail`: 15
- 后端返回 `number_reasons`，为每个主号和特别号生成一句玄学解释。
- 后端返回 `ritual_summary`，用于首页展示 AI/玄学推荐总结。
- 历史数据只做托底，不再在首页强调“历史趋势 50%”。
- 保留原有 `history_basis` 和 `personal_basis` 字段，避免分析页和旧测试断裂。

## 算法原则

- 号码排序以个人时空分、AI 数字偏好、开奖日运势为主，历史分只作为 15% 托底。
- AI 不直接返回号码，只输出五行和数字偏好；号码仍由本地算法生成。
- 玄学解释使用确定性模板生成，避免每次刷新文案飘忽。
- 重复位彩种（福彩3D、排列3、排列5）继续按位生成，允许重复。
- 非重复彩种继续保持规则范围、数量、排序合法。

## 前端体验

- 按钮文案改为“生成财运号”。
- 公式条改为“个人时空 40% / AI 命理 25% / 开奖日运势 20% / 数据托底 15%”。
- 原“历史趋势”卡片改为“数据托底”，原“个人时空”卡片改为“玄学解读”。
- 新增每个号码的玄学解释列表。
- 免责声明改为“娱乐推荐，不构成投注建议”。

## 非目标

- 不新增独立页面。
- 不做中奖承诺。
- 不让 AI 直接输出具体号码。
- 不改分析页、策略页和后台页的信息架构。

## 验证

- 预测引擎测试覆盖权重、号码解释、免责声明和字段兼容。
- API 测试覆盖首页 shell 文案和接口 payload。
- 前端 JS 语法检查。
- 全量 pytest 回归。
