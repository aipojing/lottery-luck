# 商业化历史说明

## 当前状态

商业化代码只作为历史兼容保留，生产形态处于休眠状态。

当前前端不展示支付、会员、次数包、模拟购买、模拟开通、额度剩余或付费云端记录入口，也不调用额度、支付、会员、次数包或模拟购买接口。生产 API 应保持：

```bash
LOTTERY_LUCK_QUOTA_ENABLED=false
```

历史模块和表结构可以暂时保留，以降低旧代码导入和数据迁移风险；它们不是当前上线依赖，也不构成生产付费能力。

## 部署边界

- Web 项目不得配置支付、Turso、DeepSeek 或管理类 secret。
- API 项目可以保留休眠代码所需的导入路径，但不应把商业化接口作为生产页面能力暴露。
- 后台如仍能读取旧配置，只能用于归档排查；不得作为“可购买”或“可解锁”的生产承诺。
- 文案必须继续声明本项目仅供娱乐和数据分析参考，不构成投注建议，不销售彩票，不提供代购服务，不承诺中奖或收益。

## 恢复商业化前的门槛

如未来重新启用商业化，需要另立设计和合规评审，至少补齐：

- 正式登录账号体系。
- 订单、支付、退款和风控表。
- 微信或支付宝等正规商户支付接入。
- 支付回调验签、幂等和重放保护。
- 用户权益、发票、退款和客服流程。
- 前端清晰展示付费权益且不得暗示提高中奖概率。
- 隐私、日志和数据保留策略。

在这些工作完成前，任何生产页面都不得暴露支付或额度行为。
